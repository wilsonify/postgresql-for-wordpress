# Compatibility Analysis: PostgreSQL Backend for WordPress

**Version**: 3.0  
**Status**: Draft  
**Last Updated**: 2026-07-02

---

## 1. Compatibility Policy

| Category | Support Level | Description |
|----------|--------------|-------------|
| WordPress Core | Fully Supported | All core features operate correctly on PostgreSQL. Known differences from MySQL behavior are documented in this compatibility matrix. |
| Supported WordPress Database APIs | Fully Supported | Code using `$wpdb` methods, `wpdb::prepare()`, `WP_Query`, `WP_User_Query`, `WP_Meta_Query`, `WP_Comment_Query`, and standard WordPress database abstractions works without modification. |
| Standard Themes | Expected to Work | Themes distributed through WordPress.org or custom themes using only provided WordPress APIs function correctly. |
| Plugins using the WordPress Database API correctly | Expected to Work | Plugins that interact with the database exclusively through standard WordPress APIs operate correctly. |
| Plugins issuing raw MySQL-specific SQL | Best Effort | Plugins that bypass WordPress abstractions and issue MySQL-dialect SQL directly are handled on a best-effort basis. Known incompatibilities are documented in this matrix. Support may require plugin-specific translation rules. |
| Plugins depending on MySQL server-specific behavior | Not Guaranteed | Plugins depending on MySQL-specific server features (e.g., stored procedures, MySQL-specific functions not supported by PostgreSQL, MySQL-specific index types, MySQL error code dependencies) are not guaranteed to function. |

### 2.1 Experimental Support

The following configurations have preliminary support but are not fully tested in CI:
- PHP 8.4 with PostgreSQL 17 (latest releases, tested in nightly)
- WordPress trunk/development versions
- WooCommerce beta/release candidates

### 2.2 Explicitly Unsupported

| Feature | Reason |
|---------|--------|
| PHP < 8.1 | Below minimum extension compatibility |
| PostgreSQL < 14 | Insufficient test coverage, may have version-specific SQL differences |
| MySQL < 5.7 | pgloader migration may not handle older MySQL type variants |
| Stored procedures / triggers | WordPress and its ecosystem do not use them |
| Full-text search (MATCH...AGAINST) | PostgreSQL full-text search has different syntax and semantics |
| Spatial data types | WordPress does not use spatial indexes |
| Async / parallel query execution | Not used by WordPress core |

## 3. Database Compatibility

Each section documents: MariaDB behavior, PostgreSQL behavior, expected translation behavior, known limitations, and verification strategy.

### 3.1 Schema Creation (DDL)

| Aspect | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|--------|---------|------------|-------------|-------------|--------------|
| Table options | `ENGINE=InnoDB`, `CHARSET=utf8`, `COLLATE=utf8_unicode_ci` | No ENGINE concept; charset per database/column | ENGINE, CHARSET, COLLATE stripped from DDL | None | DDL stubs |
| AUTO_INCREMENT | `id INT AUTO_INCREMENT` | `id SERIAL` or `GENERATED BY DEFAULT AS IDENTITY` | AUTO_INCREMENT → SERIAL + sequence creation | Sequence name may not match expectations for custom tables | CREATE TABLE stubs |
| UNSIGNED | `INT UNSIGNED` | No UNSIGNED keyword | UNSIGNED stripped | Values exceeding signed range will error; unlikely for standard WordPress data | CREATE TABLE stubs |
| ENUM | `status ENUM('a','b')` | No ENUM type | ENUM('0','1') → SMALLINT; general ENUM → TEXT | SMALLINT for boolean-like enums is type-safe; TEXT for general enums allows any value | DDL stubs + integration |
| BINARY/VARBINARY | `data BINARY(16)` | No BINARY type | BYTEA | None | DDL stubs |
| DATETIME | `created DATETIME` | TIMESTAMP (without timezone) | TIMESTAMP | Zero dates ('0000-00-00') not valid in PostgreSQL — converted to NOW() | DDL stubs + functional test |
| Width specifiers | `INT(11)`, `VARCHAR(255)` | No width on integer types | Width stripped from integer types; VARCHAR(n) preserved | None | DDL stubs |
| KEY/INDEX | `KEY name (col)` or `INDEX name (col)` | No inline KEY in CREATE TABLE | Extracted to separate CREATE INDEX | None | DDL stubs |
| CHARSET/COLLATION | Per-table charset settings | Per-database or per-column | Stripped from DDL | Collation-sensitive ordering may differ; WordPres uses application-level collation | Integration test |

### 3.2 Data Types

| MariaDB Type | PostgreSQL Type | Translation | Semantics Match | Risk |
|-------------|----------------|-------------|-----------------|------|
| TINYINT | SMALLINT | Direct | Approximate — SMALLINT holds larger range | Low — PHP values fit in both |
| SMALLINT | SMALLINT | Direct | Exact | None |
| MEDIUMINT | INT | Direct | Approximate — INT holds larger range | None |
| INT | INT | Direct | Exact (width stripped) | None |
| BIGINT | BIGINT | Direct | Exact | None |
| FLOAT | REAL | Direct | Approximate — both 4 bytes | Precision differences possible |
| DOUBLE | DOUBLE PRECISION | Direct | Exact | None |
| DECIMAL(p,s) | DECIMAL(p,s) | Direct | Exact | None |
| DATE | DATE | Direct | Exact | None |
| DATETIME | TIMESTAMP | Direct | Near — TIMESTAMP without timezone | Zero date handling differs; ON UPDATE CURRENT_TIMESTAMP not available |
| TIMESTAMP | TIMESTAMPTZ | Direct | Different — MySQL auto-converts to UTC; PG stores explicitly | Consistent session timezone setting required |
| TIME | TIME | Direct | Exact | None |
| YEAR | SMALLINT | Direct | Approximate — stores year as integer | Application must validate year range |
| CHAR(n) | CHAR(n) | Direct | Exact | None |
| VARCHAR(n) | VARCHAR(n) | Direct | Exact | None |
| TINYTEXT | TEXT | Direct | Exact | None |
| TEXT | TEXT | Direct | Exact | None |
| MEDIUMTEXT | TEXT | Direct | Exact — PG TEXT can hold 1 GB | None |
| LONGTEXT | TEXT | Direct | Exact — PG TEXT can hold 1 GB | None |
| BINARY(n) | BYTEA | Direct | Content match | None |
| VARBINARY(n) | BYTEA | Direct | Content match | None |
| TINYBLOB | BYTEA | Direct | Content match | None |
| BLOB | BYTEA | Direct | Content match | None |
| MEDIUMBLOB | BYTEA | Direct | Content match | None |
| LONGBLOB | BYTEA | Direct | Content match | None |
| ENUM | SMALLINT or TEXT | Converted | Semantic mismatch — SMALLINT loses constraint; TEXT allows any value | Data validation must be at application level |
| SET | TEXT array | Not implemented | Not applicable | Very low — WordPress does not use SET |
| BOOL/TINYINT(1) | BOOLEAN or SMALLINT | Converted | TINYINT(1)→SMALLINT loses boolean semantics; BOOL→BOOLEAN exact | PHP truthiness masks the difference |

### 3.3 Indexes

| Aspect | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|--------|---------|------------|-------------|-------------|--------------|
| B-tree index | Default | Default | Direct | None | DDL stubs |
| UNIQUE index | `UNIQUE KEY name (col)` | `CREATE UNIQUE INDEX name ON t (col)` | Converted | None | DDL stubs |
| FULLTEXT index | `FULLTEXT KEY name (col)` | `CREATE INDEX ON t USING GIN(to_tsvector('english', col))` | Not implemented | WordPress search relies on FULLTEXT for relevance ranking; falls back to ILIKE | Integration test |
| INDEX prefix | `INDEX name (col(10))` | No prefix support | Stripped or ignored | Loss of index size optimization; low impact for typical WordPress data volumes | DDL stubs |
| Spatial index | `SPATIAL KEY name (col)` | `CREATE INDEX ON t USING GIST(col)` | Not implemented | WordPress does not use spatial indexes | — |

### 3.4 Sequences and Identity

| Aspect | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|--------|---------|------------|-------------|-------------|--------------|
| Auto-increment | `AUTO_INCREMENT` on integer column | `SERIAL` or `IDENTITY` column | AUTO_INCREMENT → SERIAL + sequence | Sequence naming convention must be documented | DDL stubs + integration |
| Last inserted ID | `LAST_INSERT_ID()` / `mysqli_insert_id()` | `CURRVAL('seq_name')` or `RETURNING` | CURRVAL for most WordPress tables; RETURNING for INSERT rewriter output | CURRVAL fails for tables without properly named sequences; hardcoded table mapping must be maintained | Insert + insert_id integration test |
| Sequence reset | `ALTER TABLE t AUTO_INCREMENT = n` | `SELECT setval('t_seq', n)` | Direct mapping | None | Integration test |

### 3.5 Transactions

| Feature | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|---------|---------|------------|-------------|-------------|--------------|
| BEGIN / COMMIT / ROLLBACK | Standard SQL | Standard SQL | Direct | None | Integration test |
| AUTOCOMMIT | Default ON | Default ON | SET AUTOCOMMIT TO ON | None | Integration test |
| SAVEPOINT | `SAVEPOINT sp` | `SAVEPOINT sp` | Not implemented | WooCommerce may use savepoints for nested transactions | Integration test |
| LOCK TABLES | Table-level lock | No LOCK TABLES | Not implemented | WordPress uses LOCK TABLES during schema updates; may need application-level workaround | Integration test |

### 3.6 Locking

| Feature | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|---------|---------|------------|-------------|-------------|--------------|
| GET_LOCK(name, timeout) | Named advisory lock (session scope) | `pg_try_advisory_lock(key)` | Needs mapping via hash function | hash collision risk for long lock names; key must fit in bigint | Integration test |
| RELEASE_LOCK(name) | Named advisory lock | `pg_advisory_unlock(key)` | Needs mapping | Same collision risk | Integration test |
| SELECT...FOR UPDATE | Row-level lock | Row-level lock | Direct | None | Integration test |

### 3.7 NULL Semantics

| Operation | MariaDB | PostgreSQL | Compatibility | Verification |
|-----------|---------|------------|---------------|-------------|
| NULL in ORDER BY ASC | NULLs sort first | NULLs sort last (default) | **Known difference** — can be addressed with `NULLS FIRST`/`NULLS LAST` | Functional test verifying sort order |
| COUNT(column) | Counts non-NULL values | Counts non-NULL values | Compatible | Stub test |
| CONCAT('a', NULL) | Returns 'a' (ignores NULL) | `'a' \|\| NULL` returns NULL | **Known difference** — string concatenation must use CONCAT function, not `\|\|` operator | Stub test + integration |
| NULL = NULL | NULL (not TRUE) | NULL (not TRUE) | Compatible | Stub test |
| IN (NULL) | NULL (not TRUE) | NULL (not TRUE) | Compatible — `IN ()` → `IN (NULL)` | Stub test |

### 3.8 Boolean Handling

| Feature | MariaDB | PostgreSQL | Compatibility | Verification |
|---------|---------|------------|---------------|-------------|
| Boolean type | TINYINT(1) as pseudo-boolean | Native BOOLEAN | TINYINT(1)→SMALLINT; BOOL→BOOLEAN | DDL stubs |
| Boolean in WHERE | `WHERE active` works (non-zero = true) | `WHERE active` requires boolean expression | Not automatically translated — may need explicit comparison | Functional test |
| Default values | `BOOL DEFAULT 0` | `BOOLEAN DEFAULT FALSE` | Default rewritten to FALSE/TRUE | DDL stubs |

### 3.9 Date/Time Handling

| Feature | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|---------|---------|------------|-------------|-------------|--------------|
| Zero date | '0000-00-00' valid | Invalid timestamp | Converted to NOW() AT TIME ZONE 'GMT' | Semantically different — "not set" vs "current time" | DDL stubs + functional test |
| ON UPDATE CURRENT_TIMESTAMP | Auto-updates on row change | No equivalent | Not implemented | post_modified column must be set explicitly by application | Integration test |
| Timezone handling | Server timezone, automatic UTC conversion for TIMESTAMP | Configurable per session; explicit AT TIME ZONE | Session timezone must be set to UTC | Must ensure consistent session configuration | Integration test |
| Date functions | YEAR(), MONTH(), DAYOFMONTH(), DATE_ADD(), etc. | EXTRACT(), + INTERVAL, TO_CHAR() | Each function mapped individually | Complex date queries with multiple functions may interact poorly (known issue) | Stub test + integration |

### 3.10 Character Encoding and Collation

| Feature | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|---------|---------|------------|-------------|-------------|--------------|
| Default charset | utf8mb4 (4-byte UTF-8) | UTF-8 (encoding set at database level) | Database encoding set during creation | 4-byte characters (emoji) work in PostgreSQL UTF-8 | Functional test |
| Collation | utf8mb4_unicode_ci | LC_COLLATE setting | COLLATE clauses stripped from DDL | Sorting order may differ for some character sequences | Functional test |
| Character set conversion | CONVERT(expr USING charset) | No direct equivalent | Not implemented | Very low — rarely used in WordPress | — |

### 3.11 SQL Syntax

| Feature | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|---------|---------|------------|-------------|-------------|--------------|
| LIMIT m,n | `LIMIT 0, 10` | `LIMIT 10 OFFSET 0` | Rewritten | None | Stub test |
| INSERT ... SET | `INSERT t SET col=val` | Not supported | Not implemented | Plugins using this syntax fail | Stub test (known gap) |
| INSERT IGNORE | `INSERT IGNORE` | No IGNORE | INSERT → ON CONFLICT DO NOTHING | None | Stub test |
| ON DUPLICATE KEY | `ON DUPLICATE KEY UPDATE col=val` | `ON CONFLICT (col) DO UPDATE SET col=val` | Rewritten | Conflict target detection may be incorrect for composite unique keys | Stub test |
| REPLACE INTO | `REPLACE INTO t VALUES (...)` | No REPLACE | INSERT → ON CONFLICT DO UPDATE | Requires unique constraint | Stub test |
| DELETE with JOIN | `DELETE t1 FROM t1 JOIN t2` | `DELETE FROM t1 USING t2 WHERE...` | Multi-table → USING syntax | Complex join conditions may not translate correctly | Stub test |
| UPDATE with LIMIT | `UPDATE t SET col=val LIMIT 1` | Not supported | LIMIT stripped | Loss of intended behavior — may update more rows than expected | Stub test |
| DO | `DO 1` (execute with no result) | Not supported | Rewritten to SELECT 1 | None — returns a result where MySQL returns none | Stub test |

### 3.12 Identifier Quoting

| Feature | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|---------|---------|------------|-------------|-------------|--------------|
| Backtick quoting | `` `column` `` | Not valid | Backticks → double quotes | Case sensitivity: MySQL folds to lowercase; PG folds unquoted to lowercase | Stub test |
| Identifier case | Case-insensitive | Folds unquoted to lowercase | Mixed-case identifiers (e.g., `ID`) must be double-quoted | Fragile — trailing spaces in output | Stub test |
| Reserved words | Can use as unquoted identifiers in some contexts | Must be quoted | Selectively quoted based on known reserved word list | May miss some PostgreSQL reserved words | Stub test + functional test |

### 3.13 String Escaping

| Feature | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|---------|---------|------------|-------------|-------------|--------------|
| Backslash | Backslash is escape by default | Backslash is escape by default (standard_conforming_strings=ON) | `\'` → `''` | May double-escape if applied incorrectly | Stub test |
| Single quote | `''` escapes single quote | `''` escapes single quote | Compatible | None | Stub test |

### 3.14 Prepared Statements

| Feature | MariaDB | PostgreSQL | Translation | Limitations | Verification |
|---------|---------|------------|-------------|-------------|--------------|
| Placeholder syntax | `?` (positional) | `$1`, `$2` (numbered) | `?` → `$N` conversion needed | Must not convert `?` inside string literals | Integration test |
| Prepare/Execute | `PREPARE stmt FROM ...` / `EXECUTE stmt` | `PREPARE stmt AS ...` / `EXECUTE stmt` | 9 MySQLi stmt functions must be implemented | Some plugins use MySQLi stmt API directly; WordPress uses `$wpdb->prepare()` | Integration test |

## 4. MySQL Function Mapping

| MySQL Function | PostgreSQL Equivalent | Translation Status | Risk |
|---------------|----------------------|-------------------|------|
| YEAR(date) | EXTRACT(YEAR FROM date) | Implemented | Complex queries with multiple date functions may interact poorly |
| MONTH(date) | EXTRACT(MONTH FROM date) | Implemented | Same as YEAR |
| DAYOFMONTH(date) | EXTRACT(DAY FROM date) | Implemented | Low |
| DATE_ADD(d, INTERVAL n UNIT) | d + INTERVAL 'n unit' | Implemented | Low |
| DATE_FORMAT(d, fmt) | TO_CHAR(d, fmt) | Not implemented | WooCommerce reports |
| UNIX_TIMESTAMP() | EXTRACT(EPOCH FROM NOW()) | Implemented | Low |
| FROM_UNIXTIME(ts) | to_timestamp(ts) | Not implemented | WooCommerce reports |
| RAND() | RANDOM() | Implemented | Seeded RAND(N) behavior differs |
| FIELD(val, a, b, c) | CASE val WHEN a THEN 1... | Implemented | Large value lists generate verbose CASE |
| GROUP_CONCAT(col) | string_agg(col, ',') | Implemented | Separator and ordering semantics may differ |
| IF(cond, t, f) | CASE WHEN cond THEN t ELSE f END | Implemented | Boolean coercion differences |
| IFNULL(a, b) | COALESCE(a, b) | Implemented | Low |
| NULLIF(a, b) | NULLIF(a, b) | Implemented | None |
| CONCAT(a, b) | `\|\|` or CONCAT(a, b) | Implemented via `\|\|` | NULL handling differs — see Section 3.7 |
| CONCAT_WS(sep, a, b) | CONCAT_WS(sep, a, b) | Not implemented | — |
| LIKE | LIKE (case-sensitive) or ILIKE | ILIKE used for case-insensitive contexts | Case-sensitive LIKE for non-CPT queries may be wrong |
| REGEXP | `~` | Implemented | Regex syntax differences between MySQL and PostgreSQL |
| FOUND_ROWS() | No equivalent | Cached count query | Race condition under concurrent requests |
| SQL_CALC_FOUND_ROWS | No equivalent | Stripped; cached count query | Same race condition |
| GET_LOCK(n, t) | pg_try_advisory_lock(hashtext(n)) | Pending implementation | Hash collision risk for long names |
| RELEASE_LOCK(n) | pg_advisory_unlock(hashtext(n)) | Pending implementation | Same collision risk |
| UTC_TIMESTAMP() | CURRENT_TIMESTAMP AT TIME ZONE 'UTC' | Implemented | Low |
| NOW() | NOW() / CURRENT_TIMESTAMP | Implemented | None |
| CAST(a AS type) | CAST(a AS type) | Implemented with type name mapping | Low |
| CONVERT(a, type) | CAST(a AS type) | Implemented | Low |

## 5. Known Gaps by Severity

### 5.1 Critical (Must Resolve Before Production)

| Gap | Impact | Affected Requirement |
|-----|--------|---------------------|
| GROUP BY with nested WHERE subqueries loses WHERE clause | Complex queries return all rows instead of filtered set | FR-05 (content queries) |
| INSERT ... SET syntax not supported | Plugins using this MySQL-specific syntax fail | FR-14 (plugin SQL handling) |
| Date function rewrites (YEAR/MONTH) corrupt complex queries | Archive pages, admin date filters return wrong data | FR-11 (date-based queries) |
| FOUND_ROWS() race condition | Pagination counts wrong under concurrent load | FR-05 (pagination) |
| Prepared statement stubs not implemented | Plugins using MySQLi stmt API fail | FR-14 (plugin SQL handling) |

### 5.2 High (Should Resolve)

| Gap | Impact | Affected Requirement |
|-----|--------|---------------------|
| FROM DUAL not stripped | Some plugins fail on SELECT-only queries | FR-14 |
| GET_LOCK/RELEASE_LOCK missing | WooCommerce and SEO plugin lock operations fail | FR-14, FR-29 |
| Remaining driver function stubs (14 functions) | Plugins using certain MySQLi API functions fail | FR-14 |

### 5.3 Lower Priority (Future Phases)

| Gap | Impact | Target |
|-----|--------|--------|
| LOCK TABLES/UNLOCK TABLES | Schema-changing operations under concurrent load | Future phase |
| ON UPDATE CURRENT_TIMESTAMP | post_modified auto-update | Future phase |
| FULLTEXT index translation | WordPress search relevance ranking | Future phase |
| INDEX prefix support | Index size optimization | Future phase |
| Savepoints (SAVEPOINT) | WooCommerce nested transactions | Future phase |
| DATE_FORMAT support | Plugin reports | Future phase |
| FROM_UNIXTIME support | WooCommerce reports | Future phase |
